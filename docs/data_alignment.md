# f1express 数据对齐进度与规则记录 (Data Alignment Status)

本文档记录了项目在数据对齐（Data Alignment）方面的进展、处理逻辑以及待核查项。

## 1. 核心处理逻辑

### 1.1 多实体构造商积分合并 (Multi-entity Logic)
历史上部分车队在同一赛季使用多种引擎（如 Lotus-Climax 和 Lotus-BRM），FIA 将其视为独立实体。为了匹配现代统计口径：
- **逻辑**：对同一赛季内具有不同引擎/命名的同一品牌实体，分别计算其每站最高得分，然后将各实体的年度“原始分 (outof)”累加。
- **配置项**：`special_events.json` 中的 `constructor_multi_entity`。

### 1.2 历史 ID 归并 (Team ID Merges)
解决历史遗留的数据 ID 分离问题（如 McLaren BRM 曾被分配独立 ID 83）。
- **逻辑**：在重算统计前，执行 SQL UPDATE 将变体 ID 的所有比赛记录、最快圈、冲刺赛记录归并到主 ID 下。
- **配置项**：`special_events.json` 中的 `team_id_merges`。

### 1.3 特殊扣分/处罚 (Points Penalties)
处理车手积分保留但车队积分被罚没的情况。
- **全额扣除 (ALL)**：如 1995 巴西站（贝纳通、威廉姆斯燃油违规）。
- **数值扣除 (Numeric)**：如 2000 奥地利站（迈凯伦 ECU 封条缺失，扣除 10 分）。
